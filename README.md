# OPC Marketing

一个给**个人开发者 / 一人公司（OPC）**用的营销取舍 skill，只服务软件产品（App、SaaS、工具站、插件）。

市面上的 marketing skill 大多大而全，什么都能做，却很少考虑你只有一个人、每周几个小时、几乎没有预算。这个 skill 反过来：

- **先问清楚**：目标用户、目标市场、资源约束。回答太泛就追问，直到能说出"这群人聚在哪"。
- **先砍**：用 6 道门（人群、阶段、能力、周期、资源、跨市场复用）把不该做的渠道筛进"不做清单"。
- **再押注**：剩下的渠道打分，只选 1 个主攻、最多 1 个辅助。
- **说清 AI 分工**：每个渠道 AI 能代劳几成、做到几分、剩下哪些必须你本人做。

最终产出是一页纸方案，不是报告。

## 安装

把 `opc-marketing/` 目录复制到 `~/.claude/skills/` 下即可。

```bash
git clone https://github.com/easyaitech/OPC--Marketing.git
cp -r OPC--Marketing/opc-marketing ~/.claude/skills/
```

## AI 代劳度分数怎么更新

渠道卡片里的"AI 代劳度"是写死的主观判断，不在每次对话里临时联网查。原因：这类判断本质是观点，每次现查结果不稳定。

每次发版时：
1. 根据最新的 AI 能力（模型、视频 / 图像生成、Agent 工具等）逐张复核分数
2. 更新每个渠道文件顶部的"分数版本"和"更新于"
3. 在下方更新记录里写清改了哪些分数、为什么

## 使用建议

自动触发率不高：给建议类的问题，Claude 常常会直接回答而不去加载 skill，装了很多营销类 skill 时还会互相抢。想确保用上这个 skill，直接输入 `/opc-marketing`，后面跟上你的情况。


## 独立技能：OPC 产品范围取舍

`opc-product-scope` 在个人开发者提出新增功能、改变产品行为或调整体验时使用，帮助判断是否值得做并收敛最小范围；与 `opc-marketing` 的获客场景独立。明确的故障修复、纯实现问题和机械修改直接进入原有工作流程。

- 围绕核心用户任务，评估需求证据、更小方案与全生命周期成本。
- 新功能先简短取舍；明确小调整直接推进，已决定的需求不重复劝退。
- 证据不足时按成本与可逆性选择小步验证，必要质量纳入范围。
- 输出本轮重点、最小范围、暂缓 / 不做项和验证标准。

可独立安装，也可与营销技能一起安装。将 `opc-product-scope/` 复制到 `~/.codex/skills/`（Codex）或 `~/.claude/skills/`（Claude Code）。Codex 可输入 `$opc-product-scope`，Claude Code 可输入 `/opc-product-scope`，后接功能或改动需求。
